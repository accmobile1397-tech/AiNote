# Knowledge Promotion Governance
## Version 1.0

**Status:** Canonical

## Purpose

Govern the promotion of knowledge from exploratory notes and project learning into reusable canonical knowledge and, eventually, the executable Bootstrap.

## Promotion States

```text
observed
→ candidate
→ reviewed
→ canonical
→ bootstrap-proposed
→ bootstrap-approved
```

Alternative terminal states:
- `project-local`
- `deprecated`

## Gates

### Candidate → Reviewed

The observation is understandable, evidenced and sufficiently documented.

### Reviewed → Canonical

The principle is reusable and generalized beyond its original context.

### Canonical → Bootstrap Proposed

The knowledge has an actionable effect on project initialization or execution and can be expressed as a protocol, pattern, skill, template or validation rule.

### Bootstrap Proposed → Approved

Impact, conflicts, compatibility, migration and versioning have been reviewed and the change is explicitly approved.

## Anti-Contamination Rule

A project-specific implementation must never become a global standard merely because it worked once.

## Evidence

Where practical, promotion should reference project evidence, experiments, decisions or repeated observations supporting the generalized rule.

## Versioning

Bootstrap changes are versioned. Existing projects remain on their selected Bootstrap version unless they explicitly migrate.

## Governing Principle

> **Promotion is a knowledge-governance decision, not a file-copy operation.**

**End — Knowledge Promotion Governance v1.0**
